# Blink review and measured results

Natural closures were being missed because the state machine started its timer
only after the close-frame confirmation and discarded reopening in CLOSING.
It now times from the first qualifying closed sample and validates duration
when the eyes reopen. Two closed samples, reopening, face validity, and debounce
are still required. One-frame spikes remain rejected.

The live scheduler now preserves sampling deadlines across slight timing jitter
and rejects duplicate media frames. Test Lab waits for actual seek completion;
it no longer waits for a callback that may never arrive on paused video.
Model-download retries now recover, nonfinite eye scores reset safely, and a
one-eye closure cannot be classified as a complete bilateral blink.

## Public-video experiment

Source: https://www.blinkingmatters.com/research
Download: https://www.blinkingmatters.com/files/upload/research/eyeblink8.zip
The publisher labels the available data GPL-3. Videos, original annotations,
and derived signal arrays are kept outside the repository and deployment.
No custom model was trained. Only timing logic and two scalar defaults changed.

Used the first 900 decoded frames of EyeBlink8 recordings 1, 3 and 8, normalized
to 30 FPS using FFmpeg `setpts=N/(30*TB)`. Tags are matched by decoded frame
index, with one event per blink ID and a 350 ms one-to-one matching tolerance.
These excerpts are 30 seconds each, not the complete dataset. All had a face
detected in all 900 samples. The production web detector (CPU delegate) generated
the signals. Both old and new state machines received identical signals.

Recording 1 was the tuning excerpt. A 32-candidate search varied smoothing,
close threshold and duration; false positives cost three times a true positive.
Among candidates matching all three labels, chose smoothing 0.55 / close 0.46
while retaining the 80 ms duration minimum. The fixed candidate was also
checked on recording 3 before adoption, without further parameter changes.
Recording 8 was held out from
candidate selection; its poor recall was not used to further tune parameters.

| Excerpt | Before TP / FP / FN | After TP / FP / FN |
| --- | --- | --- |
| 1, tuning | 0 / 0 / 3 | 3 / 0 / 0 |
| 3, additional check | 0 / 0 / 6 | 4 / 0 / 2 |
| 8, validation | 0 / 0 / 5 | 1 / 0 / 4 |
| Total | 0 / 0 / 14 | 8 / 0 / 6 |

After: precision 100%, recall 57.1%, F1 72.7%. Validation recall is only 20%.
This small experiment supports an incremental improvement, not reliable
general accuracy or validated goggles performance. Existing synthetic regression
count metrics remain 4 TP / 0 FP / 0 FN; mean timing error rose from 12.5 ms
to 100 ms as event starts moved earlier. The approved baseline was not replaced.

## Reproduce with locally obtained data

Convert the desired AVI with FFmpeg (installed separately):

```
ffmpeg -i recording.avi -vf "setpts=N/(30*TB)" -frames:v 900 -an -c:v libx264 excerpt.mp4
node scripts/extract-video-signals.mjs excerpt.mp4 signals.json 30 /path/to/chrome
npm run import:eyeblink8 -- --input recording.tag --output labels.json --fps 30 --split validation
npx tsx scripts/evaluate-video-signals.ts signals.json labels.json report.json
npx tsx scripts/compare-revision.ts 8925ab6 signals.json labels.json comparison.json
```

The runner serves only the selected file over loopback, launches a temporary
browser, and closes it on completion. MediaPipe assets are downloaded; footage
is never uploaded. Use the same normalized frame timeline for video and labels.
Comparison with older software must replay the same signals on that revision.

## Remaining checks

Type checking, lint, all 29 unit tests, synthetic regression, and the Expo web
export passed. A 390 x 844 browser smoke test passed camera/detector startup
and stop with a synthetic camera, no horizontal overflow or runtime errors.
An explicit UTF-8 declaration fixes startup text decoding when the server
does not provide a charset. This browser test is not a physical iPhone test.

Physical iPhone camera timing, battery and goggles accuracy still need live use.
Public snippets do not substitute for those conditions. Developer Mode remains
optional. Additional diverse full-length footage and negative examples should
precede more aggressive threshold changes.

Compatible dependency patches were applied. npm still reports 17 transitive
advisories (13 moderate, 4 high), largely Expo/Metro/native build dependencies;
its proposed forced Expo downgrade was not applied. Do not expose development
servers publicly. Production remains a static GitHub Pages export.
